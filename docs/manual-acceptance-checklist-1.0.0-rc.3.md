# 1.0.0-rc.3 内容分组验收

## 推荐先看这四处

本地隔离测试已验证桌面及 390px 手机布局、组名链接筛选、区块编辑器统一改名、经典编辑器保存与成员变更。不是 NAS 或正式站验收；安装后主要确认实际主题下的效果即可。

- [ ] 文章编辑器 → 标题层 → 内容分组：填入 `W1 看见人的软弱` 并保存。
- [ ] 同季下一篇填写同组；第九篇填写 `W2 看见自己的有限`。
- [ ] 系列选择“结构化归档”后，桌面和手机显示季名、分组小标题、篇号与文章标题。
- [ ] 单篇题头显示“系列 · 季 · 组名 · 篇号”；点击组名只显示本季本组。

## 补充检查

- [ ] 保存后重新打开编辑器，已有组名可建议选择；经典编辑器同样支持输入。
- [ ] “修改此组名称”统一更新组名，其他文章显示新名、旧组链接仍有效。
- [ ] 清空本文分组并保存，只取消本文分组；其他成员保留。
- [ ] 同名组跨季独立，分组内分页及“查看完整列表”正常。
- [ ] 混合未分组文章保持原篇序，不产生“未分组”空标题；跨页时组名重新显示。
- [ ] 序文、主要文章、尾声的现有顺序不受影响；分组不会重置篇号。
- [ ] 普通系列无分组时输出不变；主题原生归档保留主题布局（分组小标题仅由结构化归档提供）。

旧的“公开结构标签”若存了周名，需人工移到“内容分组”并清空旧覆盖值；
插件不能判断哪些公开标签是周名，因此本版没有自动搬移旧标签。
文末阅读导航仍遵循原有“全系列／当前季”范围。

Publisher 端需要单独按 [接入约定](wp-publisher-content-groups-rc.3.md) 增加属性映射。
