# WP Title Layer 0.11.0 NAS 验收清单

本清单验证 0.11.0 的书籍式 Series 结构，以及 0.10.0 验收后发现的编辑边界
问题。测试目标必须是隔离的非生产 WordPress 站点。不得修改正式站点；只有已确认
属于测试用途的既有内容可以复用，并可按场景增加带明确前缀的临时内容。

## 0. 安全边界与记录

- [ ] 安装的是发布包 `wp-title-layer-0.11.0.zip`，插件列表显示 `0.11.0`。
- [ ] 记录 WordPress、PHP、主题、编辑器和站点语言版本。
- [ ] 所有新建 Series、Season、文章、分类与媒体标题均以前缀
  `WPTL 0.11 QA` 开头，并附本轮日期或短编号。
- [ ] 开始前记录原有 Series 与文章数量；复用原有样本时记录其 ID 与所做操作。
- [ ] 测试故障、损坏 rank、删除 Season、批量编辑等破坏性场景优先作用于本轮 QA
  数据；若复用原有测试内容，必须先确认对象与恢复路径。
- [ ] 若当前账号无安装插件、编辑 Series 或上传媒体权限，停止相应项并记录为
  “环境阻塞”，不得转到正式站补测。

## 1. 覆盖升级与零自动迁移

- [ ] 覆盖安装后，原有普通文章、Series 文章、Series Archive 与设置仍可访问。
- [ ] 未打开“篇序与结构”时，既有 Series 不新增已启用的书籍式结构标记，也不改变
  文章关系、旧 position、公开标签、Season 或前端顺序。
- [ ] 既有有序 Series 仍先使用 0.10 的 Sequence 初始化状态；未初始化者不能绕过
  旧顺序预览直接启用书籍式结构。
- [ ] 既有无序 Series 也先显示逐 Series 的只读结构兼容预览，而不是自动猜测角色
  范围。

## 2. 编辑器所有权边界

- [ ] 编辑普通文章时只出现一个 WP Title Layer 面板，原生标签式 Series 面板不闪现。
- [ ] 在较慢网络或强制刷新后观察加载过程，原生 “Add New Series” 面板仍不出现。
- [ ] 编辑媒体附件时不出现 WP Title Layer 面板、Title Layer 区块或 Series 控件。
- [ ] 文章列表的“快速编辑”和“批量编辑”不显示会被理解为多选标签的原生 Series
  控件；Subtitle 列与原生显示选项仍正常。
- [ ] Gutenberg 中 Series 仍为单选；选择、清除、改换 Series 后保存并刷新，值一致。
- [ ] 若测试站启用 Classic Editor，canonical meta box 只在 Gutenberg 实际关闭的
  受支持文章类型出现，且同样不允许创建 Series term。

## 3. 四种 Series 形状

分别创建以下四个隔离 Series，每个至少三篇主要文章：

| 组合 | 必测语义 |
| --- | --- |
| 平铺 + 有序 | 主要文章有自动篇号；序文／尾声／附录分轨且不占篇号 |
| 平铺 + 无序 | 主要文章沿用 Archive 排序设置；非主要轨道可移动 |
| 多季 + 有序 | 每季主要文章独立排序；完整 Series 可跨季阅读 |
| 多季 + 无序 | 各季正文无虚构阅读顺序；结构轨道仍固定在正文边缘 |

- [ ] 新建空 Series 保存后直接显示规范书籍式结构；有序者也直接具备空的规范篇序。
- [ ] 平铺 Series 的非主要角色归属全系列，不能保存单季范围。
- [ ] 多季 Series 的主要文章必须选择一个已定义 Season，不能设为全系列范围。
- [ ] 多季 Series 的序文、尾声、附录可分别选择“全系列”或“单季”。
- [ ] 清除 Series 后，遗留 role、scope、Season 不会被解释为另一个 Series 的结构。

## 4. 既有数据兼容预览

在 QA 数据中模拟“升级前已存在”的多季 Series：

- [ ] 给一篇非主要角色保留有效 Season，但不设 scope；预览将其列为范围待确认，
  不自动写成单季。
- [ ] 给另一篇非主要角色同时留下无效 Season 与空 scope；预览列为无效／不明确。
- [ ] 存在以上问题时，“启用书籍式结构”被拒绝，前端仍使用兼容行为。
- [ ] 在文章编辑器逐篇明确全系列或单季范围后，重新载入预览，问题消失。
- [ ] 预览载入后再改动成员或结构字段，旧 fingerprint 不能提交；刷新复核后才可启用。
- [ ] 启用只影响目标 Series；其他 QA Series 与所有原有 Series 不变。

## 5. 篇序与结构管理器

在多季有序 Series 中至少创建：两篇全系列序文、两篇第一季序文、三篇第一季
主要文章、两篇第一季尾声、一篇第一季附录、第二季主要文章、一篇全系列尾声、
两篇全系列附录。

- [ ] 顶部 Series 选择器可输入中文或英文名称搜索；选中后直接进入目标 Series，
  增强界面不再显示悬浮的“打开”按钮。禁用脚本时仍可用原生下拉框和按钮。
- [ ] 任一已初始化的有序短系列，即使没有启用书籍式结构，也显示“篇序”视图及
  拖动、前后插入和撤销功能；不要求重新初始化。
- [ ] 启用高级结构后，“篇序”视图仍可用，并与主要文章轨道呈现同一 canonical
  顺序；“结构轨道”视图单独管理非主要角色。
- [ ] 轨道选择器列出全系列序文、每季序文／主要文章／尾声／附录、全系列尾声和
  全系列附录；不产生无意义的“全系列主要文章”轨道。
- [ ] 拖动可以在同一轨道重排，不能把文章隐式拖入另一个角色或 Season。
- [ ] 纯键盘移动与鼠标移动结果一致，并有清楚的焦点与状态反馈。
- [ ] 通过搜索锚点将文章精确放到跨页目标之前／之后，后续主要文章不需手工改号。
- [ ] 页面过期时 revision 冲突阻止覆盖；刷新后可继续。
- [ ] 撤销只还原最近一次仍匹配的轨道移动，不覆盖之后的编辑。
- [ ] 非主要文章的 Public structure label 可显示 `0-1`、`0-2`、`附录 A`；它不改变
  私有排序或主要文章自动篇号。
- [ ] 无序 Series 的主要文章轨道仅供上下文查看，不能手动排序；序文、尾声和附录
  轨道仍可移动。

## 6. 前端 Archive、Single 与导航一致性

- [ ] 完整多季 Archive 的结构顺序为：全系列序文 → 各季序文／主要文章／尾声／
  附录 → 全系列尾声 → 全系列附录。
- [ ] `?wptl_season=数字` 只显示目标季的序文、主要文章、尾声与附录，不混入全系列
  序文、尾声或附录。
- [ ] 单篇标题题头显示正确 Series、Season 和主要文章篇号；序文／尾声使用公开
  结构标签时不占正文序号。
- [ ] 有序 Series 的上一篇、下一篇、起点、当前位置与总数使用相同的完整结构顺序。
- [ ] 选择“当前季”导航范围时，五项导航共同停在季边界；全系列条目不混入单季导航。
- [ ] 无序 Series 不生成主要文章上一篇／下一篇；其结构化 Archive 仍正确固定非主要
  轨道。
- [ ] 草稿、定时、私密、密码保护与回收站文章不进入公开 Archive／导航集合。
- [ ] Theme Archive、Structured Archive、Subtitle、Excerpt、特色图、Series 图标和
  Category 返回链接的 0.9／0.10 行为无回归。

## 7. Series Health 与异常数据

- [ ] Series 总览可按名称或别名搜索；搜索结果只包含匹配项，翻页保留搜索词，清除搜索
  后恢复完整列表。
- [ ] Health 的范围／角色视图能定位空 scope、非法 scope、无效 Season、未知 role。
- [ ] 不同轨道可使用相同私有 rank 而不被误报为重复；同一轨道的重复／损坏 rank
  才被报告。
- [ ] 无序 Series 的主要文章不因没有 rank 被报错，已启用结构的非主要轨道仍检查
  rank。
- [ ] 故意删除一条 QA 非主要文章 rank 后，文章不会从 Manager 消失，而是位于轨道
  尾部并可修复。
- [ ] Health 始终只读；所有修复链接进入文章编辑器或结构管理器。

## 8. 中文、英文与响应式界面

- [ ] 简体中文界面统一显示“序文／前言、尾声／后记、全系列、单季、篇序与结构、
  结构轨道”，没有误译成归档页或季名。
- [ ] 英文界面显示源文案，内置标题分隔符使用英文标点；切换语言不改 canonical 数据。
- [ ] “篇序与结构”、文章侧栏、Series 编辑页、Health 与 Structured Archive 在桌面
  和手机宽度无横向溢出，按钮和轨道标签可辨识。

## 9. 清理与结论

- [ ] 记录失败项的 URL、文章／Series ID、复现步骤、预期与实际结果；必要时附截图。
- [ ] 只删除本轮明确创建的临时文章、Series、分类和媒体；复用的原有测试样本保留，
  除非删除本身就是已记录的测试步骤。
- [ ] 清理后核对复用样本的关系与预期相符，并记录有意保留的测试变化。
- [ ] 将未执行项标为“未测”并说明权限或环境原因，不将其误记为通过。

通过标准：所有已执行的 P0 数据边界、四形态结构、兼容预览、轨道排序和前端
一致性项目通过；未测项目有明确环境原因；没有改动正式站，NAS 的测试性改动均有
对象 ID 与结果记录。
