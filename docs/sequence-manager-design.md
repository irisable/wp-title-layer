# Series Sequence Manager 设计契约

状态：**0.10.0 已按本契约实现并通过正式站点人工验收**。0.11.0 保留本契约的
正文 sparse rank、revision、journal 与稳定 Season 身份，并在统一的“篇序与结构”
页面中把篇序管理与可选结构轨道分为两个视图；scope／role 契约见
[0.11.0 功能地图](feature-map.md)。

这份文档取代“手工把 21 / 22 改成 210 / 220，再用 215 插入”一类
临时方法。稀疏数字只是插件内部实现，不是作者需要理解或填写的
内容字段。

## 1. 产品决定

- 有序 Series 的作者操作是“把这篇放在某篇之前／之后”或拖动排序，
  不是手工维护整数位置。
- 内部排序、自动篇号与人工显示标签是三个独立概念。
- 插入一篇后，后续自动篇号可以变成 23、24 等，但不需要逐篇编辑。
- 既有 `wptl_sequence_position` 不删除、不批量覆盖；它是 0.9.x 的兼容来源，
  不是 Sequence Manager 启用后的 canonical order。
- `wptl_sequence_label` 继续保留。为空时显示自动篇号；有值时可显示
  `21A`、`序一`、`0-1` 等编辑标签。
- 无序 Series 的正文仍然没有阅读顺序。Sequence Manager 不会因为它的
  Archive 需要排列就把它改成有序 Series。

## 2. 语义与数据模型

### 2.1 三种值

| 关注点 | 来源 | 用途 |
| --- | --- | --- |
| Canonical rank | 新增私有 post meta `wptl_sequence_rank` | 插件内部比较顺序，编辑器不直接暴露 |
| Automatic ordinal | 根据 canonical order 运行时计算 | 普通篇目的 1、2、3……，不存储为新的人工顺序 |
| Public label override | 现有 `wptl_sequence_label` | 少数需要固定或非数字编号的篇目 |

`wptl_sequence_rank` 是正整数，默认按固定大间隔分配。插入时取相邻两值
的中间值；只有当局部已无空位时，服务端才在当前排序范围内重新
均匀分配。间隔大小是实现细节，不是公开数据契约。

### 2.2 排序范围

- flat + ordered：整个 Series 是一个排序范围。
- seasoned + ordered：每个 Season 是一个排序范围，自动篇号在季内计算。
- Series 的“整系列／当前季”阅读导航设置只决定导航是否跨季，
  不改变季内篇号语义。
- 一般正文（现有空 role 或 `article`）进入自动篇号；`intro`、`epilogue`、
  `appendix` 在 0.11.0 可按需启用完整书籍式结构。是否启用这些高级轨道，
  不决定有序正文能否使用篇序管理。

自动篇号的编辑集合包含已发布、定时、私密、草稿和待审的正常文章，
不包含回收站、自动草稿和 revision。因此未发布篇目可以预留正式位置。
阅读进度仍只统计当下真正可公开阅读的集合，所以在存在未发布篇目时，
题头篇号与“第 x / y 篇”的公开阅读位置可以不同。

### 2.3 激活标记

新增 Series term meta `wptl_sequence_schema_version`。

- 缺失或为 `0`：整个 Series 继续使用 0.9.x 的 `wptl_sequence_position`；
  零散的 rank 不影响前台。
- 为 `1`：整个 Series 已由 Sequence Manager 管理，所有顺序消费者统一
  读取 rank。

这个 term meta 是提交点。初始化必须先写完、校验全部篇目的 rank，
最后才将版本从 `0` 改为 `1`；中途中断时线上仍使用旧顺序。

## 3. 季份的稳定公开编号

0.10.0 同时给每个 Season 定义增加正整数 `public_id`，与下列字段分工：

- `key`：文章与 Season 的稳定内部关系，继续保留；
- `label`：前台显示的“抵达篇”、`S1` 等名称；
- `sort`：季份排列顺序；
- `public_id`：公开 URL 使用的稳定数字身份。

新 Series 从 1 开始分配；既有 Series 先预览“按当前 `sort` 将得到 1、2、3”，
由管理员明确确认后写入。Season 改名或重排不改变已分配的 `public_id`，
删除后的数字不自动复用。

生成链接使用 `?wptl_season=1`、`?wptl_season=2`。原有
`?wptl_season=season`、`season-2`、`s1` 等 key URL 仍可解析，并在安全的
GET 请求中重定向到数字 canonical URL。不覆盖 Season 名称的可见文字。

## 4. 管理界面

WP Title Layer 菜单中的 **篇序与结构** 提供两个彼此独立的视图：有序 Series
始终可用的 **篇序**，以及按需启用的 **结构轨道**。

1. 通过可搜索选择器选择一个 Series，选中后直接打开，不再要求第二次点击；若脚本
   不可用，保留原生下拉框和“打开”按钮。选择有序 Series 后默认进入篇序视图；
   seasoned Series 再选择一季。
2. 列表显示自动篇号、标题、发布状态、日期、当前公开标签和原生编辑链接。
3. 鼠标可拖动；键盘可上移、下移、移到开头／末尾；也可通过
   “放在……之前／之后”精确插入。
4. 旧数据中重号、缺号或非法位置进入“待编排”区；未经人工放置，
   或未明确选择“按日期追加”，不猜测它们的正式顺序。
5. 保存后提供“撤销上一次编排”；只在相关 rank 仍与记录的新值一致时
   才能撤销，避免覆盖之后的编辑。

旧 Series 在 0.10 已完成初始化时，升级后直接看到篇序管理，不需要启用书籍式
结构，也不需要重新初始化。启用高级结构后，篇序视图继续映射到主要文章轨道。

对大型 Series，页面不依赖一次提交全部文章。“移动某篇到目标前／后”
是服务端的最小原子操作；客户端可分页、搜索目标或按需加载，不会因为
文章跨页就无法插入。

文章编辑器的行为：

- 未启用 Manager 的旧 Series 仍显示旧位置字段和升级说明。
- 已启用 Manager 的 Series 不再编辑内部 rank，只显示当前自动篇号、
  可选 Public label 以及“在 Sequence Manager 中移动”链接。
- 新文章或改换 Series／Season 后若没有 rank，安全追加到目标范围末尾，
  并在编辑器明确告知。之后可在 Manager 移动，不阻止保存。

## 5. 写入、权限与并发契约

- 所有操作校验 nonce、Series taxonomy 编辑权限和所受影响文章的
  `edit_post` 权限。
- 客户端只提交 Series、Season、被移动文章与相邻锚点；成员集合、
  新 rank 和是否需要再平衡均由服务端重新确定。
- 每个排序范围维护 revision。请求携带已读 revision；期间若有他人编辑，
  返回冲突并要求重载，不会以旧页面覆盖新顺序。
- 初始化、再平衡和撤销先写 non-autoload journal，再分批写 post meta，最后提交
  schema version / revision。中断后可恢复或值校验回滚。
- 任何撤销只修改本次 journal 记录且当前值仍匹配的元数据。
- 直接写入旧 `wptl_sequence_position` 不能悄然改变已管理 Series 的顺序；
  Series Health 应提示“旧字段已被写入但当前不生效”。

## 6. 升级与恢复

0.10.0 激活本身不写文章 rank，也不更改现有前台顺序。每个旧 Series
独立升级：

1. 只读预览现有季、位置、重复、缺失和文章状态。
2. 按旧位置填入可确定部分；重复和缺失进入待编排区。
3. 管理员确认完整顺序和 Season public IDs。
4. 冻结当前成员与源值指纹，分批写入 rank。源值漂移进入冲突，不扩大
   已审阅批次。
5. 完整校验后才把 Series 的 schema version 提交为 1。

初始升级 journal 支持回退：只删除它所创建且仍保持记录值的 rank，不动
旧 position、label、Season 关系和文章内容。已经用 Manager 做过新编排后，
不将“降回 0.9”冒充为无损撤销；正式降级工具必须先预览将当前顺序
物化为旧 position 所产生的批量写入，不默认执行。

## 7. 唯一排序服务

下列路径必须共用同一个 canonical sequence service，不得各自重新实现顺序：

- Theme Series Archive 查询；
- Structured Series Archive 及分页；
- Single 题头中的自动篇号；
- 上一篇、下一篇、从头阅读和进度；
- Series Health；
- Sequence Manager 本身的列表与锚点搜索。

排序服务的同序最后保险值是 post ID，只用于使损坏或中断数据仍可重现；
正常的 Manager 数据不应依赖它表达内容顺序。

## 8. 为 0.11.0 书籍式结构预留的边界

Sequence Manager 的 rank 属于一个“排序轨道”。0.10.0 只有平铺 Series 或各季
正文轨道；0.11.0 可以在不更换 rank 字段的前提下增加：

- Series 级序文；
- 每季序文；
- 每季正文；
- 每季尾文；
- Series 级尾文；
- 附录。

有序 Series 的正文轨道有阅读顺序；无序 Series 的正文仍按自身 Archive
规则排列，但多篇序文／尾文在各自轨道内使用同一 rank 机制。因此 0.10.0
必须先完成，0.11.0 不再发明第二套排序器。

## 9. 验收与测试

### 核心行为

- 把新篇插入原第 21 与 22 之间，用户只操作这篇；之后题头、
  两种 Archive、导航和进度得到同一顺序。
- 连续在同一空位插入直至触发再平衡，前台顺序不跳动、不丢篇、不重复。
- flat / seasoned、整系列 / 当前季导航均正确。
- 自动篇号会随插入变动；人工 public label 保持原文。
- 草稿预留位置，发布后不需要再编排；回收站文章不占自动篇号。

### 兼容与安全

- 仅激活 0.10.0 不写旧 Series，前台顺序与 0.9.1 一致。
- 旧 position 含 0、缺号、重号、无效 Season、草稿和私密文章的预览准确。
- 在初始化每一批之后模拟中断，未提交 Series 仍读旧顺序，继续或回退均幂等。
- 无权限请求、过期 nonce、过期 revision、成员漂移和锚点不属于该范围时全部失败关闭。
- 撤销不覆盖在原操作之后被他人改过的 rank。
- 旧 Season key URL 可达并转向稳定数字 URL；中文改名不改 URL。

### 界面与规模

- 鼠标、触屏和纯键盘均能完成插入，动作结果通过 `aria-live` 读出。
- 分页或搜索后可将文章放在另一页的锚点前／后。
- 以长 Series 验证有界查询、再平衡批次、恢复和 Manager 页面响应时间，
  不把“浏览器一次渲染全部文章”作为正常路径。
- 继续通过 WordPress 6.5 / PHP 7.4 与当前 WordPress / PHP 8.3 双矩阵，
  并对源码及最终 ZIP 各执行一次。
